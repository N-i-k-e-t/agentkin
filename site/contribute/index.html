Make your first useful contribution.

Choose a bounded task, test it honestly and let a human review the result.

Pick a track

  • Code and tests: contract validation, mocked examples or a small tool proposal.
  • Docs: reproduce the setup and fix a specific gap.
  • Web and accessibility: report and fix a real mobile or keyboard issue.
  • Design: improve original project assets with clear provenance.

Contribution sequence

  1. Read CONTRIBUTING and GOVERNANCE.
  2. Open an issue for substantial work; wait for a maintainer's approved-to-build label.
  3. Fork and branch from current develop using the documented prefixes.
  4. Add a contract, README and mock tests for agent/tool/integration changes.
  5. Use git commit -s and open a PR into develop.
  6. Fix failing checks; wait for the required human approvals before merging.

What counts as accepted work?

A merged useful contribution is accepted work. An opened PR is still pending. No one needs to star the project to participate, and no job or certificate is promised.

Review turnaround depends on actual maintainer availability. The operator cannot approve or merge its own PR.
