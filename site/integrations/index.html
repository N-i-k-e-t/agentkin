Connect with intention.

An integration owns auth, rate limits, retries and the permission boundary for an outside service.

The connection contract

The integration template records service name, version, auth method, environment key names, rate limits, data reads/writes, mock location and test location. These are design requirements, not currently connected services.

Start read-only and mocked

  1. Define the smallest permission scope the task needs.
  2. Add key names only to .env.example; real values stay local.
  3. Keep public fixture responses in mock/ and cover expected failures.
  4. Document what data is read, written or stored.
  5. Wrap a service capability in a typed tool before an agent consumes it.

GitHub, MCP-compatible services or other platforms can be proposed as integrations. Their logos, names and APIs do not imply a partnership or implemented compatibility.

Security comes first

Never submit tokens or personal records in an issue or PR. Report vulnerabilities through the security policy. If a key is exposed, revoke and rotate it before relying on deleting a file.
