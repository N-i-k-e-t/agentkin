Family of AI Agents / foundation

Small tools. Clear boundaries.

A tool exposes one typed capability, with explicit inputs, outputs and test evidence.

What belongs in a tool

Use a tool for a specific capability an agent can call. Define an input schema and output schema, document errors and declare the integration used for outside access. Tools do not hide credentials in source code.

ContractQuestion it answers
Input schemaWhat data can the caller provide?
Output schemaWhat result and error shape can it expect?
Integration usedWhich component owns external permissions?
Mock testsCan someone reproduce behavior without keys?

Example proposal: a mock search tool

A first proposal could accept a query, use a fixed fixture integration and return titled result records. That would demonstrate a boundary; it would not be live web search. Add real provider support only with a separate permissions and test review.

Current status

The repository contains the tool contribution contract. There is no implemented tool library or published package yet.
