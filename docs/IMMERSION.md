# Student contribution and immersion pathway

This is an opt-in open-source learning pathway, not an advertised job or guaranteed paid internship. Do not promise salary, placement, credits, a certificate or employment. An institutional internship arrangement needs separate owner/institution approval and written terms.

## Roles and small deliverables

| Track | Week-one deliverable | Evidence | Reviewer |
|---|---|---|---|
| Python/agent contributor | Validate one agent contract; then propose a mocked example | Test command, issue and PR | Technical maintainer |
| Integration contributor | Propose read-only GitHub adapter with mock fixtures | Permissions matrix, failure cases, tests | CODEOWNER |
| Web/accessibility contributor | Fix one reproducible mobile/a11y issue | Before/after and browser checks | Site maintainer |
| Documentation contributor | Reproduce setup, correct one gap | Fresh-clone steps and PR | Docs reviewer |
| Community research contributor | Verify three community rule pages; prepare one tailored draft | Source URLs and rule evidence | Community coordinator |

## Four-week suggested pathway

1. Orientation: read governance/license/security, choose a track, agree a realistic weekly time budget. A mentor must opt in; do not invent assigned mentors.
2. First contribution: claim a bounded issue, reproduce it, branch and sign off. A docs correction is valid work; do not manufacture activity.
3. Build a small useful improvement with mock tests and paired review when capacity permits.
4. Write a short learning reflection linking evidence. Review the next task or close the pathway without penalty.

## Tracking and privacy

Use `docs/outreach/immersion-tracker.csv` as an EMPTY schema template. Keep populated records in a private workspace; public Git history must not include applications, personal emails/phone numbers, university IDs, age, grades, attendance or private feedback. Use a consented public handle in public issues only. Do not collect sensitive information.

States: interested → consented → oriented → task-selected → building → PR-open → changes-requested → merged → reflected → completed; paused/withdrawn may occur at any stage. Record evidence, not hours as a proxy for contribution. A submitted PR is not a merged contribution.

Suggested weekly check-in: task, blocker, next action, reviewer availability and evidence link. Measure time to first response, accepted useful work and participant feedback. No leaderboards ranking students by stars or spam volume. Certificates, if ever introduced, require verified criteria and owner approval.
